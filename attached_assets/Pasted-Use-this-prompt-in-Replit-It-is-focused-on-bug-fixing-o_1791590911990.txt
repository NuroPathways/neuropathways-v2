# Replit Prompt: Full UI Bug Fix Pass Without Changing App Functionality

I need you to do an all-around UI bug fix pass for NeuroPathways.

Do not redesign the app.

Do not remove features.

Do not change how the app works.

Do not change the product structure, routes, user roles, or app logic unless needed to fix bugs.

This is a bug fix and polish pass focused on broken buttons, weird selected states, text overflow, layout issues, and visual glitches.

---

## 1. Main Problems to Fix

I am running into weird UI bugs across the app:

1. Some buttons show check marks next to them.
2. Some buttons show circles next to them.
3. When I click certain buttons, the whole button or item becomes grayed out.
4. Some clicked items look permanently disabled even when they should still be usable.
5. Some buttons look like checkbox/radio options even when they are normal action buttons.
6. Some text is spilling outside of gray text bubbles/cards.
7. Some AI chat messages or support text does not wrap correctly.
8. Some text overflows outside cards instead of staying inside.
9. Some cards still look awkward, blocky, or broken after clicking.
10. Some UI states are inconsistent between pages.

Fix these issues across the whole app.

---

## 2. Do Not Confuse Buttons With Selection Controls

Audit every button component.

Normal action buttons should not show:

- checkmarks
- empty circles
- radio icons
- checkbox icons
- selected indicators

unless the control is actually meant to be a checkbox, radio button, or selectable option.

For normal buttons like:

- Open Support Steps
- I Need Help Now
- Start Preparation
- Done
- Log What Happened
- Upload Plan
- Ask AI
- Add Behavior
- Add Goal
- Show Details
- Save
- Skip
- Try Today

they should look like buttons only.

They should not show a circle or checkmark next to the text.

---

## 3. Fix Button Click States

When a user clicks a normal button, it should not stay grayed out unless the action is truly disabled or loading.

Correct button states:

### Default

Button is normal and clickable.

### Hover

Subtle color change only.

### Active / Pressed

Short pressed state only while clicking.

### Loading

Show spinner or loading text only while the action is processing.

### Disabled

Only use disabled styling when the user cannot click it.

Do not leave buttons gray after being clicked.

Do not make a button look disabled after it was pressed unless the action is complete and intentionally unavailable.

---

## 4. Fix Selected State Styling

If something is a selectable card, selected state is allowed.

Examples:

- behavior selection
- child selection
- intensity selection
- goal selection
- checkbox confirmation
- radio group

But selected states should be visually clean.

Use selected styling only for actual selectable options.

Selected option style:

- light teal/blue background
- thin border
- small checkmark only if useful
- no giant icon
- no grayed-out disabled look

Do not apply selected/checked styling to normal action buttons.

## 5. Audit Component Library

If one component is being used for both buttons and selectable choices, split it into two:

1. `ActionButton`
2. `SelectableOption`

Do not reuse a radio/checkbox-style component for normal actions.

## 6. Fix Text Overflow in Gray Bubbles and Cards

Some text is spilling outside gray message bubbles or cards.

Fix text wrapping everywhere.

Apply safe wrapping rules to:

- AI chat bubbles
- support step bubbles
- gray text boxes
- task cards
- activity cards
- source explanation boxes
- goal cards
- document cards
- log cards
- mobile cards

CSS rules should include:

```css
overflow-wrap: anywhere;
word-break: break-word;
white-space: normal;
max-width: 100%;
```

For chat bubbles:

```css
.chat-bubble {
  max-width: 100%;
  overflow-wrap: anywhere;
  word-break: break-word;
  white-space: normal;
}
```

For message text:

```css
.message-text {
  max-width: 100%;
  overflow-wrap: anywhere;
  word-break: break-word;
  white-space: pre-wrap;
}
```

Do not allow text to extend outside of bubbles.

Do not allow long AI responses, URLs, file names, or source labels to break layout.

## 16. Accessibility and Focus States

Keep accessibility, but make focus states clean.

Keyboard focus should show a subtle outline.

Focus should not look like selected/checked unless the item is actually selected.

```css

  outline: 2px solid rgba(47, 125, 161, 0.45);
  outline-offset: 2px;
}
```

Do not use focus state to add checkmarks, circles, or gray disabled styles.
