# NeuroPathways — Unifying the Old and New Parent Interfaces

After reviewing your screen recording and our previous redesign decisions, I agree that **the best solution is to combine the strongest parts of both interfaces into one consistent parent experience**.

The recording shows two noticeably different experiences:

- **Independent parent account:** The newer interface has a simpler Home page, daily activities, Practice, Help Now, and parent-focused navigation. However, Practice has overlapping navigation, and some pages have become unnecessarily complicated.
- **Clinician-connected family account:** The older interface includes a family dashboard, child profiles, clinician-connected information, and the more structured Goals & Milestones presentation. However, the dashboard is too busy for everyday parent use.

The older Goals & Milestones screen has several elements worth preserving: its clear title, child selector, progress information, milestone structure, and easy-to-identify actions. The newer Practice screen, by contrast, has page tabs for Activities, Learn Why, My Routines, and Saved for Later, followed by another set of Understand, See, Try, and Reflect controls inside activities. That creates unnecessary navigation complexity.

### The most important fix

**How a parent account was created should not determine which interface the parent sees.**

A parent who signs up independently and a parent whose account was created by a clinician should use the same parent interface.

The difference should be the information and permissions available to them, not the design.

A clinician-connected parent may have additional approved plans, assignments, and care-team features. An independent parent may have starter support and their own uploaded documents. Both should have the same Home, Help Now, Practice, Goals & Milestones, and Document Center.

I would keep the current NeuroPathways colors, desktop sidebar, and overall brand identity while making the parent experience more spacious and consistent.

## The implementation prompt for Replit

The following prompt is designed to **fix the underlying split between the two parent interfaces**, not just change their appearance.

It allows Replit to make major workflow and UI changes while requiring it to preserve existing data, permissions, and working features.

Copy this into Replit and attach the October 17 screen recording.

# Replit Agent Prompt: Unify NeuroPathways Parent Portals and Combine the Best Features of Both Designs

## Primary Objective

I want you to perform a substantial UI and workflow consolidation of the existing NeuroPathways application.

Currently, NeuroPathways has two different parent-facing experiences depending on how the account was created.

**Problem 1 — Clinician-created accounts**

When a clinician creates a client or family account, the parent receives the older version of the NeuroPathways interface.

This version includes a family dashboard, child profiles, document management, Goals & Milestones, and clinician-connected features.

**Problem 2 — Independently created parent accounts**

When a parent creates an account directly, without a clinician, they receive the newer NeuroPathways interface.

This version includes the simplified Home page, Help Now, Practice, activities, Goals, and newer navigation.

**I do not want two different parent interfaces anymore.**

I want one unified parent-facing application that combines the best functionality and design choices from both versions.

You are authorized to make major changes to the UI, routing, component structure, and navigation where necessary.

However, preserve the existing backend functionality, data, authentication, document processing, and permissions.

**Do not change the existing NeuroPathways color scheme.**

Use the attached screen recording as a visual reference.

## PHASE 1 — Investigate the Existing Application Before Changing Anything

Before modifying the application, inspect the codebase and identify why two different parent-facing interfaces exist.

### Investigate the following

1. How independent parent accounts are created.
2. How clinician-created parent/family accounts are created.
3. How account roles are assigned.
4. How account type determines which dashboard loads.
5. How linked children and families are retrieved.
6. How clinic and clinician relationships are stored.
7. Where the older parent UI components are located.
8. Where the newer parent UI components are located.
9. Whether the two interfaces use different API endpoints.
10. Whether they use different data structures for documents, goals, activities, and logs.

Pay particular attention to conditional routing involving account roles or origins.

For example, investigate any existing distinctions equivalent to:

- parent
- caregiver
- family
- clinician
- client
- independent parent
- clinic-connected parent
- invited account
- self-created account

These distinctions may still matter for permissions and data access.

**They should not determine whether the parent receives the old or new UI.**

Create or consolidate around one shared parent application interface.

For example:

`UnifiedParentPortal`

The actual component name should follow the application's existing conventions.

```text

       |

       |          |
```

The user interface should be shared.

Do not resolve this problem by removing role-based security or merging independent user records.

## Two additional issues I noticed in the recording

**1. The old Goals page has a good layout, but some goal names need fixing.** In the clinician-connected version, I can see a goal displayed as something like `F4 goal 13:32:51`. That is not meaningful to a parent. Keep the milestone layout, but display a readable goal title derived from an actual goal description. Don't invent a new clinical objective to replace a missing title.

**2. The current Practice page is trying to do too many things on the same screen.** It combines category navigation, a running activity, learning stages, and activity controls. These should become separate levels of navigation: Practice → Activity → Guided Steps. That will make the experience feel much less confusing.

### What I would prioritize

I would have Replit fix the **two-parent-interface problem first**, before making further cosmetic changes.

Once both account types use the same parent application, changes to Home, Practice, Goals, and Documents will be much easier to maintain. Otherwise, you'll continue improving one experience while the other remains outdated.

One limitation: the recording lets me compare the interfaces, but I haven't verified the underlying repository code, so the exact route and component names in the prompt are implementation instructions rather than confirmed findings.
