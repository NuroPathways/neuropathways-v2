# Replit Prompt: Redesign Parent Home Page Around Tasks, Activities, and Daily Utility

Update the NeuroPathways parent/caregiver home page so it feels more useful day-to-day.

The app should not only help during a crisis. Parents also need simple activities, practice tasks, and small things to do with their child based on the behavior plan.

Keep all existing features working. Do not remove Support Now, documents, behavior library, AI chat, logs, uploaded plans, or goals from the app backend.

But redesign the **parent home page** so it is focused mostly on:

- daily tasks
- child activities
- practice steps
- support routines
- quick wins
- plan-based actions
- logging what happened

The home page should feel like:

**“Here is what I can do with John today.”**

Not just:

**“Here is John’s current behavior and goal.”**

---

## 1. Keep the Main Header

Keep the main page wording focused on the selected child.

The top section should still say something like:

**Today’s Support for John**

or

**Support for John**

Keep the selected child/client name visible.

If multiple children are linked, allow the user to switch children.

Do not remove the selected child context.

---

## 2. Keep “I Need Help Now” Directly Under the Header

Keep the red urgent-support button near the top.

Button:

**I Need Help Now**

Subtext:

**Get guidance from John’s saved support plans**

This should stay highly visible.

This is for urgent moments.

The rest of the home page should be for daily utility and practice.

---

## 3. Remove Goal-Focused Layout From the Parent Home Page

The parent home page should no longer be built around a large “Current Goal” card.

Remove or de-emphasize the large goal section from the desktop parent home page.

Do not delete the goals feature from the app.

Goals can still exist in:

- Goals page
- behavior support cards
- clinician dashboard
- document scan output
- AI extraction
- task/activity generation logic

But the parent home page should not be dominated by:

- Current Goal
- goal status
- goal analytics
- clinical goal language

Instead, translate goals into practical tasks and activities.

Example:

Instead of showing:

**Current Goal: Complete one small step**

Show:

**Today’s Task: Start with one small step before offering a break.**

---

## 4. New Parent Home Page Structure

Use this home page order:

## Top Section

**Today’s Support for John**

Small subtext:

**Plan-based tasks, activities, and support steps for today.**

---

## Urgent Support Card

Large red card:

**I Need Help Now**

Subtext:

**Open support steps for a stressful moment.**

---

## Today’s Tasks

This should be the main section of the home page.

Title:

**Today’s Tasks**

Subtitle:

**Small steps based on John’s support plan.**

Show 2–4 task cards.

Each task card should include:

- task title
- why it helps
- how to do it
- estimated time
- related behavior
- source label
- done button
- log button

Example task cards:

### Start Small Before Homework

**Why it helps:** Task refusal can increase when the task feels too big.  
**Try this:** Ask John to complete one small step, then offer a short break.  
**Time:** 5 minutes  
**Related support:** Task Refusal  
Buttons: **Mark Done** / **Log What Happened**

### Practice Asking for a Break

**Why it helps:** Break requests can replace refusal or escalation.  
**Try this:** Practice saying or pointing to “break” before starting a task.  
**Time:** 3 minutes  
Buttons: **Mark Done** / **Log Practice**

---

## Activities to Try

Title:

**Activities to Try With John**

Subtitle:

**Simple practice activities you can do at home.**

Show 2–3 activity cards.

Each activity should be based on:

- selected behavior
- uploaded plan
- starter support
- clinician-reviewed plan if available
- parent logs
- current support needs

Examples:

### First-Then Game

Use a simple first-then routine with a preferred activity.

**Example:** First put away two toys, then choose a game.

### Calm Body Practice

Practice one calming step when John is already calm.

**Example:** Take three slow breaths together, then praise calm body.

### Transition Countdown

Practice moving from one activity to another with a timer.

**Example:** “Two more minutes, then shoes.”

Each activity card should include:

- activity name
- what to do
- when to use it
- related behavior
- mark done button
- log button

---

## Practice This Skill

Title:

**Practice This Skill**

Show one simple skill from the behavior plan.

Examples:

- Ask for a break
- Use first-then
- Stop when called
- Move to calm space
- Use safe hands
- Follow transition warning

Card format:

**Skill:** Ask for a break  
**Practice:** Before starting homework, model “break please” and let John try it once.  
**Use when:** John starts refusing or getting frustrated.  
Button: **Practice Done**

---

## Quick Actions

Title:

**Quick Actions**

Buttons:

- Log What Happened
- Upload a Plan
- Add Behavior
- View Support Library
- Ask AI Chat

Use large buttons.

Do not make these small text links.

## Behavior Support Library Preview

Show a smaller preview section lower on the home page.

Title:

**Behavior Support Library**

Show active behaviors first.

Each card should show:

- behavior name
- status
- open support steps

Statuses:

- Starter Support
- Based on Uploaded Plan

This section should not dominate the home page.

The daily tasks and activities should be the main focus.

## 5. Task and Activity Generation Logic

The app should generate home page tasks and activities from the selected child’s support data.

Sources, in priority order:

1. clinician-reviewed plan
2. clinician-uploaded behavior plan / treatment plan / BIP / FBA
3. parent-uploaded plan
4. starter behavior support
5. recent behavior logs
6. parent-selected behavior and goal

Each generated task/activity should include:

- child_id
- parent_user_id
- behavior_id
- related_support_card_id
- source_type
- source_document_id if applicable
- task_title
- task_description
- why_it_helps
- steps
- estimated_time
- status
- created_at
- completed_at
- logged_at

Source types:

- starter_template
- parent_uploaded_plan
- clinician_uploaded_plan
- clinician_reviewed
- recent_log_pattern

---

## 6. Source Labels

Every task/activity should clearly show where it came from.

Use labels:

**Starter support**

**Based on uploaded plan**

**Based on uploaded plan · not yet reviewed by a clinician**

**Reviewed by clinician**

Do not pretend a parent-uploaded plan is clinician-reviewed.

Do not invent clinician approval.

---

## 7. Task Statuses

Tasks should have simple statuses:

- Not Started
- Done
- Skipped
- Logged
- Needs Review

Parent actions:

- Mark Done
- Skip Today
- Log What Happened
- Save for Later

Do not make this feel like a clinical form.

## 10. Examples Based on Task Refusal

If John’s active behavior is Task Refusal, generate examples like:

### Today’s Task

**Start with one small step**

Ask John to do only the first part of the task before offering a break.

Buttons:

- Mark Done
- Log What Happened

### Activity

**First-Then Practice**

Practice: “First one problem, then two-minute break.”

### Skill

**Ask for a Break**

Prompt John to ask for a break before refusing or escalating.

### Log Prompt

**Did John return to the task after support?**

Options:

- Yes
- Not yet
- Partially
- I’m not sure

---

## 11. Examples Based on Elopement

If active behavior is Elopement / Running Away, generate:

### Today’s Task

**Practice stopping at a boundary**

Practice stopping at the door, driveway, or room boundary.

### Activity

**Safety Stop Game**

Practice “stop” and “come back” in a safe area.

### Skill

**Use a safety cue**

Practice responding to a short cue like “stop” or “come back.”

---

## 12. Examples Based on Meltdowns

If active behavior is Meltdowns, generate:

### Today’s Task

**Practice calm space before escalation**

Show John the calm space when he is already calm.

### Activity

**Calm Body Practice**

Practice breathing, squeezing a pillow, or using a grounding tool.

### Skill

**Ask for help**

Practice asking for help before frustration builds.

---

## 13. Do Not Make Home Page Too Clinical

Avoid parent home page language like:

- intervention protocol
- maladaptive behavior
- treatment fidelity
- clinical goal objective
- behavior reduction target
- compliance task

Use simple language:

- task
- activity
- practice
- support step
- try this today
- what helped
- log what happened

---

## 14. AI Chat Should Support Tasks and Activities

AI Chat should be able to answer questions like:

- What activity can I do with John today?
- What should we practice for task refusal?
- What is one small thing I can do before homework?
- What should I log after trying this?
- Can you make this easier for a younger child?

AI should answer from:

- uploaded plan
- support card
- starter template
- logs
- clinician-reviewed plan if available

If no plan-based task exists, AI should say:

**I don’t see a plan-based activity for that yet. I can suggest a general starter activity, or you can upload a plan for more personalized support.**

---

## 15. Logging From Tasks

When a parent marks a task/activity done, ask a very short follow-up:

**How did it go?**

Options:

- Helped
- Somewhat helped
- Did not help
- Not sure

Optional note:

**Anything you noticed?**

This should create a log entry connected to:

- child_id
- behavior_id
- task_id
- activity_id
- parent_user_id
- timestamp
- helpfulness rating
- note optional

This gives clinicians better feedback later.

---

Do not remove:

- Support Now
- I Need Help Now
- Support Steps
- Behavior Support Library
- Goals page
- Logs
- Upload Plan
- AI Chat
- Documents
- child selector
- parent account creation
- clinician account features

This is a home page redesign and utility improvement.

---

## 17. Final Goal

The parent home page should no longer feel like a static dashboard.

It should feel like a useful daily support page.

A parent should open the app and immediately see:

- support for John
- urgent help if needed
- what to do today
- activities to try
- skills to practice
- quick logging
- upload plan option
- behavior support access

The home page should clearly communicate the real NeuroPathways product:

**NeuroPathways turns behavior plans into real-time support blocks, daily tasks, activities, and feedback loops parents can actually use at home.**
