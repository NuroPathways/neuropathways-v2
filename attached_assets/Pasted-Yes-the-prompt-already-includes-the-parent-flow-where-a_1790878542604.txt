# Add-On Section: Preserve Parent Self-Signup, Parent-Owned Accounts, and Parent Document Uploads

Add this to the existing NeuroPathways parent-facing prompt.

Important clarification: parents must still be able to create their own NeuroPathways accounts independently. The app should not require a clinician invitation, clinic connection, clinician code, or pre-existing clinic account for a parent to start using the free parent version.

The parent-facing free version should support two paths:

1. **Parent-created account**
   - Parent signs up directly from the landing page.
   - Parent creates their own account using email and password.
   - Parent adds their child.
   - Parent chooses one behavior.
   - Parent chooses one goal.
   - Parent gets starter support immediately.
   - Parent can upload documents later.

2. **Clinician-created / clinician-invited account**
   - Clinician creates or invites a parent/caregiver account.
   - Parent receives invite, username/password, or email link.
   - Parent is linked to the clinician’s tenant/clinic and assigned child/client profiles.

Both flows must work.

Do not remove or break direct parent self-signup.

---

## 1. Parent Self-Signup Must Remain Available

The landing page must include a clear parent signup path.

Buttons should include:

- **Start With One Behavior**
- **Upload a Plan Later**
- **I Already Have an Account**

When parent clicks **Start With One Behavior**, the app should allow the parent to create their own account.

Parent signup should support:

- email
- password
- confirm password
- parent first name

Do not require:

- clinician invite
- clinic code
- referral ID
- treatment plan upload
- diagnosis
- insurance
- long intake form
- Replit account
- external developer account

After signup, route the parent directly into Parent Quick Start.

---

## 2. Parent-Owned Workspace / Account Structure

For parent-created accounts, create a parent-owned workspace.

This can be called:

- parent_workspace
- parent_free_account
- parent_owned_account

The important requirement is that self-created parent accounts must have their own secure account space even if they are not connected to a clinic yet.

Parent-created account records should include:

- parent_user_id
- parent_profile_id
- parent_name
- email
- role = parent
- account_type = parent_free or parent_owned
- workspace_type = parent_owned
- linked_child_ids
- created_at
- updated_at

Each child created by the parent should include:

- child_id
- parent_user_id
- parent_profile_id
- workspace_id
- child_name or nickname
- age optional
- notes optional
- selected_behavior
- selected_goal
- support_card_id
- document_ids
- behavior_log_ids
- created_at
- updated_at

Do not store parent-created children as undefined family.

Do not require clinic_id for parent-created free accounts unless the parent later connects to a clinic.

If the backend requires tenant_id for every record, create a parent-owned tenant/workspace automatically for self-signup accounts.

Example:

tenant_type = parent_workspace  
tenant_id = generated parent workspace ID  
owner_user_id = parent_user_id

---

## 3. Parents Must Be Able to Upload Their Own Documents

Parents must be able to upload their own documents to their own child/profile inside their parent-owned account.

This should be available after setup from:

- dashboard
- child profile
- Upload Plan Later card
- Support Now upgrade prompt
- document section

Parents should be able to upload:

- treatment plan
- behavior plan
- BIP
- FBA
- school support plan
- IEP-related support document if they choose
- safety plan
- crisis plan
- session notes if they have them
- parent notes
- PDF
- DOC
- DOCX
- images only if supported

The upload flow should say:

**Upload a plan to make your support steps more personalized.**

Do not force upload during onboarding.

Do not remove upload access after onboarding.

---

## 4. Parent Upload Ownership and Privacy

Documents uploaded by parents should belong to that parent-owned workspace and selected child profile.

Each parent-uploaded document should include:

- document_id
- parent_user_id
- child_id
- workspace_id or tenant_id
- uploaded_by = parent
- upload_source = parent_upload
- document_type
- original_file_name
- generated_title
- storage_path
- scan_status
- created_at
- updated_at

Parent-uploaded documents should not automatically become visible to a clinic or clinician unless the parent explicitly connects with a clinic or grants access.

If the parent later connects to a clinician, add a sharing/permission step:

**Do you want to share this child’s uploaded documents with your clinician?**

Options:

- Share all documents
- Choose documents to share
- Do not share right now

---

## 5. Parent Upload Scanning

When a parent uploads a document, the system should scan it and use it to upgrade the child’s starter support.

The scan should:

- identify document type
- extract behaviors
- extract goals
- extract triggers
- extract support strategies
- extract calming strategies
- extract crisis/safety steps if present
- detect duplicate information
- detect conflicts with existing starter support
- update Support Now cards
- update goal blocks
- update AI chat knowledge base
- preserve source references

The label should change from:

**Starter Support**

to:

**Based on your uploaded plan**

Do not label it as clinician-reviewed unless a clinician actually reviewed it.

Use this label when parent uploaded the document but no clinician reviewed it:

**Based on your uploaded plan. Not yet reviewed by a clinician.**

If a clinician later reviews it, change label to:

**Reviewed by your clinician.**

---

## 6. Parent Upload Should Not Override Clinician-Approved Plans

If a child profile already has clinician-approved plans, parent-uploaded documents should not automatically override clinician-approved guidance.

Use priority labels:

1. Clinician-reviewed support
2. Clinician-uploaded document-based support
3. Parent-uploaded document-based support
4. Starter support

If parent-uploaded guidance conflicts with clinician-approved guidance, flag:

**Conflict detected. Clinician review recommended.**

Do not show conflicting unsafe instructions to parents as final guidance.

---

## 7. Parent-Owned AI Chat

Parents who create their own account should still be able to use AI chat for their uploaded documents.

AI chat should answer from:

- starter behavior support if no documents exist
- parent-uploaded documents if documents exist
- clinician documents if the parent later connects to a clinician and has access

Before clinician review, AI chat should include this disclaimer when answering from parent-uploaded documents:

**This answer is based on the document you uploaded and has not been reviewed by a clinician.**

AI chat should not pretend the information is clinician-approved unless it is.

---

## 8. Parent Dashboard Upload Access

The logged-in parent dashboard should include:

## Today’s Support

- I Need Help Now
- Current Behavior
- Current Goal
- Log What Happened
- Upload Plan

The **Upload Plan** card should always remain available.

Upload card text:

**Make this more personalized**  
Upload a behavior plan, school support plan, or treatment plan when you are ready.

Button:

**Upload a Plan**

After upload and successful scan, show:

**Your support steps were updated from your uploaded plan.**

---

## 9. Parent-Created Account Can Later Connect to a Clinic

A parent-created account should be able to connect to a clinic later without losing data.

If a clinician invites the same parent later, the app should not create a duplicate broken account.

Instead, allow account linking.

When linking parent-created account to clinician/clinic:

- preserve parent_user_id
- preserve child profiles
- preserve uploaded documents
- preserve behavior logs
- preserve starter support history
- add clinic_id / tenant_id relationship if needed
- add clinician_id
- ask parent what documents to share
- avoid duplicate children
- avoid duplicate goals
- avoid duplicate behavior cards

If duplicate child records are detected, prompt for merge review.

Example:

**We found an existing child profile named John. Do you want to connect this profile to your clinician instead of creating a duplicate?**

---

## 10. Parent-Created Account Security

Parent-created accounts should be secure and isolated.

Rules:

- Parent can only see their own account.
- Parent can only see children they created or are linked to.
- Parent can only upload documents to their own child profiles.
- Parent cannot see clinic clients unless explicitly linked.
- Clinic cannot see parent-uploaded documents unless parent grants access.
- Changing a URL or child_id should not expose another parent’s child or documents.

All parent-created records must be scoped by:

- parent_user_id
- child_id
- workspace_id or tenant_id

## Final Requirement

Do not make NeuroPathways clinician-only.

The parent free version must allow parents to independently:

1. create their own account
2. add their own child profile
3. choose a starter behavior
4. choose a starter goal
5. use starter support immediately
6. upload their own documents later
7. have those documents scanned
8. upgrade support cards based on uploaded documents
9. keep documents private unless they choose to share with a clinician

This is essential for the free parent version and parent testing flow.
